# Tauro DA322 Holoscan MIPI Adapter — hardware reference

Transcribed from the *DA322 User Manual, Revision 1.6* (Tauro Technologies, 2026-02-23). Verify any
value against the manual before using it in constraints. FPGA: **LFCPNX-100-9CBG256I** (U4).

## Connectors

| Designator | Description |
|---|---|
| J1A, J1B, J1C, J1D | 22-pin MIPI CSI-2 camera connectors (CAM1–CAM4), 4 lanes, ≤1500 Mbps/lane, 300 mA @ 3.3 V each |
| J2 | FPGA programming header (Tag-Connect, JTAG) |
| J3 | SFP+ cage (1GbE / 10GbE, XFI to FPGA) |
| J4, J5 | MFP (multi-function pin) I/O FFC connectors, 11 GPIO each |
| J7 | Molex Micro-Lock Plus power input, 12 V (4.5–17 V) |

Compatible boards listed by Tauro: DA325 GMSL adapter, Arducam B0249 (IMX477), Arducam B0353, Geekworm X1300 HDMI→CSI-2.

## MIPI CSI-2 connectors J1A–J1D (22-pin) — FPGA balls

| Pin | Signal | Net | J1A | J1B | J1C | J1D |
|---|---|---|---|---|---|---|
| 22 | +3.3 V | +3P3V | – | – | – | – |
| 21 | I2C data | CAM_I2C_SDA | H9 | G4 | H13 | D15 |
| 20 | I2C clock | CAM_I2C_SCL | H10 | G3 | H14 | D16 |
| 18 | Reference clock (2.8 V level) | CAM_MCLK_2P8V | H3 | G2 | J7 | J5 |
| 17 | Camera enable | CAM_EN | F7 | F6 | E4 | E3 |
| 15 | Data lane 3 + | MIPI_D3_P | M6 | L4 | T14 | K16 |
| 14 | Data lane 3 − | MIPI_D3_N | N6 | M4 | T13 | L16 |
| 12 | Data lane 2 + | MIPI_D2_P | P6 | L3 | R14 | K13 |
| 11 | Data lane 2 − | MIPI_D2_N | R6 | L2 | R13 | L13 |
| 9 | Clock lane + | MIPI_CLK_P | P8 | N2 | R12 | L12 |
| 8 | Clock lane − | MIPI_CLK_N | R8 | P2 | T12 | K12 |
| 6 | Data lane 1 + | MIPI_D1_P | T6 | M2 | N12 | K11 |
| 5 | Data lane 1 − | MIPI_D1_N | T5 | M1 | P12 | L11 |
| 3 | Data lane 0 + | MIPI_D0_P | T8 | P1 | N11 | L14 |
| 2 | Data lane 0 − | MIPI_D0_N | T7 | N1 | M11 | K14 |
| 1, 4, 7, 10, 13, 16, 19 | Ground | GND | – | – | – | – |

Pinout matches the Raspberry Pi / Jetson Orin Nano 22-pin CSI convention, hence the FRAMOS FPA-A/P22
adapter (pin 17 = IS_RST_IN, 18 = MCLK_IN, 20/21 = I2C, 22 = 3V3).

### Lane configuration register

`LANE_SETTING_ADDR = 0x3000_Y028` (Y = MIPI interface index 0–3), bits `[2:1]`:
`0x0` → 1 lane, `0x1` → 2, `0x2` → 3, `0x3` → 4. Example: `python hs_ctl.py 0x30000028 --set 0x6` (CAM1, 4 lanes).

## Programming header J2 (Tag-Connect TC2030-IDC-NL via TC-LATTICE adapter, HW-USBN-2B)

| Pin | Signal | Ball |
|---|---|---|
| 1 | +3.3 V | – |
| 2 | FPGA_TMS | G7 |
| 3 | FPGA_TDI | F5 |
| 4 | FPGA_TCK | E2 |
| 5 | GND | – |
| 6 | FPGA_TDO | F4 |

Radiant Programmer settings: cable USB2/FTUSB-0, TCK divider ≥ 3, device LFCPNX-100, Target Memory
"External SPI Flash Memory (SPI FLASH)", Port JTAG2SPI, Operation Erase/Program/Verify, flash
SPI Serial Flash / Micron / MT25QL256 / 8-pin W-PDFN.

## Clocks

| Ref | Net | Frequency | I/O | Ball |
|---|---|---|---|---|
| Y3 | CLK_125M_OSC | 125 MHz | CMOS | H5 |
| Y4 | ETH_REFCLK_P / ETH_REFCLK_N | 161.1328125 MHz | LVDS | D10 / E10 |

Hardware-assisted IEEE 1588 (PTP) timestamping is integrated.

## Status LEDs

| Ref | Label | Meaning |
|---|---|---|
| D2 | PGOOD | all power rails in regulation |
| D3 | DONE | FPGA configured |

## Vendor-added registers (Hololink register space)

| Register | Address | Description |
|---|---|---|
| USER_CSR | 0x7000_0000 | bit0 ST_CLEAR (RW): reset latched MIPI_DT_STAT data (not cleared while stream running) |
| MIPI_DT_CTRL | 0x7000_0004 | [7:0] CAM1, [15:8] CAM2, [23:16] CAM3, [31:24] CAM4 reference CSI data type; only matching packets forwarded; reset 0x00 |
| MIPI_DT_STAT | 0x7000_0008 | same layout, RO, latched detected data type (0x00/0x01 not latched) |

Example: `python examples/hs_ctl.py 0x70000004 --set 0x2A2B` (CAM1 → 0x2B RAW10, CAM2 → 0x2A RAW8).

## Firmware / OTA

- Vendor bitstream `fpga_cpnx_da322_3454_2511.bit` (HSB IP v2511), flash size 1,954,573 B, flash range 0x0–0x1D0000.
- OTA: `python3 scripts/generate_manifest.py --manifest manifest_da322.yaml --version 2507 --fpga-uuid 2b6485ba-a2c4-4b58-aee2-b4d5e623927e --cpnx-file <bit>` then `program_taurotech_da322 manifest_da322.yaml`. Do not interrupt power during programming.

## Not documented by Tauro — balls taken from the DA326 reference design

The manual omits these; the CertusPro-NX reference design in holoscan-sensor-bridge 2.7.0
(`fpga/nv_mipi_ref_design/mipi_cpnx_ref_design/build/constraints/fpga_cpnx.pdc`, written for the
two-camera sibling DA326) uses the same balls as the manual for everything it shares with the DA322
(J1D/J1B MIPI, camera I2C, CAM_MCLK, Ethernet refclk), so its remaining assignments are the working
assumption for our build — **to be confirmed on the DA322 by a first passthrough bitstream**:

| Function | Ref-design port | Ball |
|---|---|---|
| Reset | `RESET_N` | H1 |
| 10G SERDES | `ETH_RXD_P/N`, `ETH_TXD_P/N` | C8 / B7, A9 / A8 |
| SFP+ control | `SFP_TX_DIS` (only control pin used) | F9 |
| Control I2C (EEPROM) | `CTRL_I2C_SDA/SCL` | H7 / H6 |
| PoC I2C | `I2C_POC_SDA/SCL`, `POC_EN`, `POC_INT_L` | E14 / E15, F12, F11 |
| Config flash (QSPI) | `FLASH_SPI_MCSN`, `MSCK`, `SDIO[3:0]` | E5, E7, D4 C1 C2 D5 |
| Camera 0 (= J1D) | `MIPI_CAM_CLK[0]` L12/K12, `DATA[0..3]` K13/L13, K11/L11, L14/K14, K16/L16 | matches J1D D2, D1, D0, D3 |
| Camera 1 (= J1B) | `MIPI_CAM_CLK[1]` L3/L2, `DATA[4..7]` L4/M4, M2/M1, N2/P2, P1/N1 | note the manual lists N2/P2 as the J1B clock and L3/L2 as D2 — one of the two is a lane swap to verify |
| Camera reset / clock | `CAM_RST` H4, `CAM_MCLK` H3 (FPGA-generated, 27 MHz PLL output in the reference) | CAM_MCLK = manual's J1A pin 18 ball |
| GPIO | `GPIO[10:0]` J3 J4 J9 E6 J8 F7 G6 G5 H2 F2 F3 | `GPIO[5]` = F7 = the manual's J1A CAM_EN, i.e. CAM_EN is driven as Hololink GPIO (matches what the host code does) |

Still open: CAM_EN polarity is confirmed HIGH = on from the bring-up; MCLK is FPGA-driven in the
reference (our modules carry their own 37.125 MHz oscillator and ignore pin 18).

## Host defaults from the manual

- Board IP 192.168.0.2; vendor host example 192.168.0.77/24 (HSB default is 192.168.0.101/24)
- `net.core.rmem_max = 31326208`; `HOLOLINK_AFFINITY=<core>`; Jetson: `isolcpus=2`
- Build: `git checkout 6930609 && git apply da322_*.patch && sh docker/build.sh --dgpu` (manual shows `--igpu` for Jetson); run `sh docker/demo.sh`
